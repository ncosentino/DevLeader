# datalayer-interfaces-example - Data Layer Abstraction with Interfaces in .NET

This multi-project solution demonstrates the Dependency Inversion Principle applied to data access in .NET. The architecture separates concerns across five projects: a core `DataLayer` project defining `IModel`, `IReadModel`, and `IWriteModel` interfaces; an `ApplicationLayer` with `IStorage` and `TwoStringStorage`; and two concrete implementations for SQLite and MySQL. The console application wires everything together using an in-memory SQLite database.

By depending on abstractions rather than concrete data access implementations, the application layer remains completely decoupled from any specific database technology. You can swap between SQLite and MySQL (or add new providers) by simply changing which `IModel` implementation is instantiated, without modifying any application logic. This is a foundational pattern for building testable, maintainable .NET applications.

## Getting Started

### Prerequisites
- .NET Framework 2.0 or compatible runtime
- Projects in the solution: `DataLayer`, `ApplicationLayer`, `DataLayer.Sqlite`, `DataLayer.MySql`

### Running the Project
```bash
cd datalayer-interfaces-example
dotnet run
```
